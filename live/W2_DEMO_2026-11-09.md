## 1. Demo API (`demo/api.py`, `demo/agent.py`)

- **Quote.** A request without payment gets HTTP 402 with the price, the payee, a fresh `callId` (32 random bytes), the accepted chains, an expiry and a private `claim`.
- **Payment.** The agent calls `SpendWallet.pay(payee, price, callId)` through `forge script script/Loop.s.sol --sig "payCall(uint256,address,uint256,bytes32)"`. The key is read only inside forge. It then repeats the request with `X-Payment: <chainId>:<txHash>:<callId>` and `X-Payment-Claim`.
- **What the API checks.** It reads the receipt itself and serves only if all of these hold:
  - the tx succeeded;
  - a `Paid(callId)` came from a wallet registered for that chain in the deployment file, with exactly the quoted payee and amount;
  - **the first budget-token `Transfer` after that `Paid` log was emitted by the token contract itself, from that same wallet, to the payee, for exactly the amount**;
  - the callId was issued by this API, is unexpired and unused;
  - the claim matches.

  The callId is then recorded as used, persisted to disk, under one lock.
- **Refused pay.** `Refused(callId)` from a registered wallet gets 402 with one of two states:
  - **amber**, "budget on its way, retry in ~5 s" (top-up from the pool), or "~30 min, retry in ~310 s" (from another chain);
  - **red**: cap reached (cap − spent today < price), STOP, payee, per-call cap, or the coordinator paused (debt > 0).

  The quote stays open, so the agent pays the same callId again after amber. A refused pay moved no money.
- **The hint is not the check.** The amber/red classification reads the coordinator (`capOfDay`, `poolOf`, `frozen`), the system contract's `debt` and the wallets' `buckets(today)`. It is a hint only. The spending assertion is the checker's, from Transfer logs.
- **Agent exit codes:** 0 data, 10 amber with no time left, 11 red, 12 rejected, 4 forge failed. After a forge failure it never pays a second time blind.

**Found in self-review and fixed before commit:** the callId is public as soon as the agent's tx is on-chain. Without a second secret, anyone watching the chain could present the agent's payment first and take the data. The per-quote `claim` closes that, and it has its own test and mutant (K below).

## 2. Checker (`script/checker.py`)

- **What it counts.** Every chain and every wallet in `DEPLOYMENTS_FILE`. It sums the budget token's `Transfer` logs with `from` = a wallet (topic-1 OR list) within the UTC day by that chain's block time, and never the wallet's counter. A transfer to the wallet's own vault is a return and is listed apart; everything else is spent.
- **Day boundaries.** These come from timestamps by bisection, bracketed from the head by the recent block time: about 20–30 block reads, never a block count.
- **Chunking and pacing.** Measured read-only on 09.11:
  - Base Sepolia's public RPC refuses `eth_getLogs` over 200 blocks (`-32614`, HTTP 413) and more than 25 requests/s (HTTP 429 / `-32007` per batch item). It makes blocks every 0.2 s (~432,000 a day).
  - Unichain Sepolia refuses over 1000 blocks (HTTP 400). It makes blocks every 1 s.
  - So: 200- and 1000-block chunks, JSON-RPC batches paced to 20 requests/s. A refused range is split and retried; a rate refusal waits and retries. A full Base Sepolia day takes ~1.5–2 min.
- **Cap and exit code.** The cap is `capOfDay(d)` on Lasna, or `--cap-usd`. Exit 1 if any day is over, 2 on an RPC error.

## 6. What is left

- **The demo API has not run against the live deployment.**
  - The live wallets allowlist the deployer as payee (`PAYEE_ADDRESS` in `LIVE_LOOP.md`), so the API's payee must be that address.
  - The coordinator is paused (debt). An over-allowance call there gets red "coordinator paused" until it is funded.
  - A live run needs agent pays (transactions), so it is not done here.
- **Wording for the UI and video.** The amber/red hint reads wallet counters and the coordinator. The headline "CAN STILL LEAVE TODAY" should come from the checker's Transfer sums (it prints "can still leave").
- **Finality.**
  - The API accepts at 0 confirmations by default (`--min-confirmations`), so a reorg after serving would cost the seller.
  - The checker reads at head, so a day still running is labelled partial.
- **Coverage and performance.**
  - The checker does one day at a time: ~2,160 queries per Base Sepolia day, rate-paced.
  - A dashboard would need to keep a cursor instead of re-reading the day.
- **Demo scope.**
  - Quotes are kept in a local JSON file with no pruning.
  - One registered wallet per chain (the code accepts a `wallets` list; untested with more than one).
- **Not x402.** The real x402 path (ERC-1271, Circle USDC, a wallet balance equal to today's allowance) is future work.
